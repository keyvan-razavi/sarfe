## Local payment review and operational order reporting — November 16, 2026

Added a nonproduction `PaymentAttempt` table and customer-facing local simulator. The server requires `MOCK_PAYMENTS_ENABLED=true`, refuses all production environments, verifies same-origin JSON requests and a signed-in customer, and only accepts an active owned reservation. Attempts are independently idempotent and persist their scenario, reserved amount, currency, and timestamp. An approved scenario leaves the order in `RESERVED`; it never calls BitPay, moves funds, fulfills the order, or becomes a sales metric. Checkout shows localized line items and a provisional subtotal; prices and stock are revalidated by PostgreSQL when creating the reservation. With the local mock flag on and no policy configured, checkout clearly labels zero shipping/tax as an estimate for local review only.

Owner order search now supports status, inclusive UTC date bounds, customer name/email/phone, order ID, and SKU. `/admin` adds date-filtered daily reservation activity and counts by current status. Reports intentionally omit monetary totals. A timezone conversion defect found in the first Postgres run was fixed by returning database date buckets as ISO date strings. Shared PostgreSQL integration tests now run sequentially to prevent cross-file transaction contention. `npm run db:deploy` reports no pending migrations on local `sarfe_store`.

Integrated evidence on November 16, 2026: lint, TypeScript, all 19 default tests, Prisma validation, production build, and all 16 PostgreSQL integration tests pass. The payment integration test confirms attempts persist and remain isolated from order status and reservation stock; admin integration tests verify date/customer/order/SKU filters and daily report totals. ## Checkout foundation review — November 16, 2026

Implemented the `/checkout` page and `/api/checkout` reservation endpoint. Shared UI fields and storefront shell support Persian/Sorani RTL. The API requires same-origin JSON with a 32 KiB body cap, validates customer/address and variant quantities, expires due reservations opportunistically, then delegates to the existing serializable order service. Only server-loaded product/variant values determine money and inventory. The UI presents the server-calculated total and reservation expiry, and clearly states no payment was taken. Missing server policy settings or PostgreSQL disables checkout; production additionally requires `CHECKOUT_ENABLED=true`. The current configurable policy accepts fixed shipping/tax amounts in integer minor units with stable labels; it is not a legally reviewed or destination/rate-based tax implementation. Lint, TypeScript, 13 test files, Prisma validation and production build pass.
